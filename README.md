# Отчет по лабораторной работе: Поэтический агент с использованием методов ML и RL для генерации и анализа стихов

### 1. Теоретическая база

Данная лабораторная работа посвящена разработке интеллектуального агента, способного **генерировать, анализировать и улучшать стихотворения на русском языке**. Задача генерации связного, ритмически и стилистически выверенного текста относится к сложным проблемам **обработки естественного языка (NLP)** и **творческого искусственного интеллекта**. В основе системы лежит гибридный подход, комбинирующий несколько современных методов машинного обучения.

Для генерации текста применяется **трансферное обучение** на основе предобученной языковой модели **GPT-2**, адаптированной для русского языка. Для оценки качества стихов используется **нейросетевой критик (PoetryCritic)**, архитектура которого построена на **BiLSTM** и механизме **внимания (Attention)**, что позволяет анализировать контекст и различные аспекты текста (рифма, размер, стиль). Дополнительно для семантической оценки задействована модель **BERT**.

Ключевой особенностью проекта является применение **обучения с подкреплением (Reinforcement Learning, RL)**. Агент (на основе архитектуры **Actor-Critic**) помещается в среду (`PoetryEnvironment`), где его действия по редактированию строки (добавление/замена слов, завершение строки) оцениваются **функцией вознаграждения**. Таким образом, агент учится последовательно улучшать текст, максимизируя итоговую награду, которая формируется из оценок рифмы, размера и других критериев.

Для грамматического анализа и проверки согласованности используется библиотека **Natasha**, предоставляющая инструменты морфологического разбора для русского языка. Весь процесс управления и взаимодействие с пользователем осуществляются через **графический интерфейс (GUI)**, созданный на базе **Tkinter**.

### 2. Описание разработанной системы

**Принцип работы системы:**

1.  **Ввод и инициализация:** Пользователь через графический интерфейс вводит тему (промпт) и выбирает желаемый стиль (лирический, юмористический, философский). Система инициализирует все компоненты: генератор, анализатор, переписыватель, нейросетевые модели и RL-агента.
2.  **Генерация стиха:** Создается исходный вариант стихотворения. Система использует два параллельных пути:
    *   **Шаблонный генератор (`generator.py`):** Заполняет заранее подготовленные ритмические шаблоны словами из тематических банков данных.
    *   **Нейросетевой генератор (`GPT2PoetryGenerator`):** Использует дообученную модель GPT-2 для создания текста на основе промпта.
    Оба варианта оцениваются, и выбирается лучший.
3.  **Многоуровневый анализ:** Сгенерированный стих анализируется модулем `analyzer.py` по чек-листу:
    *   **Рифма:** Проверяется тип и качество рифмовки (AABB, ABAB и др.) с использованием Natasha.
    *   **Размер:** Определяется и проверяется единообразие стихотворного метра (ямб, хорей и т.д.).
    *   **Стиль:** Оценивается соответствие выбранному стилю по наличию ключевых слов.
    *   **Соответствие цели:** Измеряется тематическая схожесть с исходным промптом.
    *   **Грамматика:** Выполняется базовая проверка.
    Результатом анализа является общий балл и список диагностируемых проблем.
4.  **Улучшение стиха:** Если найдены проблемы, запускается цикл улучшения:
    *   **Классическое улучшение (`rewriter.py`):** На основе диагностики применяются правила и шаблоны для замены слабых слов, исправления рифмы и размера с учетом грамматики (Natasha).
    *   **RL-улучшение (`rl_agent.py`):** Состояние стиха (в векторной форме) передается RL-агенту. Агент выбирает действия для модификации текста в среде. Полученное вознаграждение от среды (основанное на улучшении оценок анализатора) используется для обучения политики агента. Этот процесс может итерироваться.
5.  **Формирование результата:** Создается итоговый отчет (`reporter.py`), в котором представлены оба варианта стиха, детальный анализ, список внесенных улучшений и сравнительная статистика.

**Архитектура системы (основные модули):**

| Модуль | Назначение | Ключевые технологии/Алгоритмы |
| :--- | :--- | :--- |
| **`agent_core.py`** | **Центральное ядро.** Координирует поток данных между всеми компонентами. | Паттерн "Фасад", управление состоянием. |
| **`generator.py`** | **Первичная генерация.** Создает стихи по шаблонам. | Шаблонное заполнение, стохастический выбор, простые эвристики для рифмы и ритма. |
| **`analyzer.py`** | **Контроль качества.** Оценивает стих по заданным критериям. | Анализ окончаний, подсчет слогов, векторная семантика (BERT), сравнение с эталонами. |
| **`rewriter.py`** | **Правило-базированное улучшение.** Исправляет выявленные недостатки. | Поиск и замена по правилам, использование синонимов, грамматическая коррекция (Natasha). |
| **`neural_models.py`** | **Нейросетевые модели.** GPT-2 для генерации, PoetryCritic и BERT для оценки. | Transformer (GPT-2, BERT), BiLSTM + Attention (PoetryCritic), PyTorch. |
| **`rl_agent.py`** | **Обучение с подкреплением.** Оптимизирует процесс улучшения стихов. | Архитектура Actor-Critic, Policy Gradient, среда с дискретными действиями. |
| **`grammar_natasha.py`** | **Грамматический анализатор.** Предоставляет интерфейс для лингвистического анализа. | Морфологический разбор, лемматизация, проверка согласованности. |
| **`main_ml.py`** | **Пользовательский интерфейс.** Визуализация процесса и результатов. | Tkinter, асинхронная обработка событий, многопоточность. |

**Алгоритмические этапы работы:**
1.  **Инициализация:** Загрузка моделей, данных (шаблоны, стили, рифмы) и конфигурации.
2.  **Последовательная обработка запроса:** Строгое выполнение этапов: генерация → анализ → принятие решения об улучшении → RL/правила → финальный анализ.
3.  **Обучение в реальном времени:** RL-агент обновляет свою политику (нейронную сеть) на основе наград, полученных в каждом сеансе улучшения.
4.  **Сбор статистики:** Система записывает метрики по каждому запросу для последующего анализа эффективности.

### 3. Результаты работы и тестирования системы

Была разработана и протестирована полностью функционирующая система, включающая все запланированные модули. В результате:

1.  **Рабочий прототип:** Создан поэтический агент с графическим интерфейсом, способный принимать запрос пользователя и возвращать сгенерированное стихотворение, его анализ и улучшенную версию.
2.  **Интеграция ML/RL:** Успешно интегрированы предобученные нейросетевые модели (ruGPT-3, ruBERT) и реализована архитектура RL-агента. Агент способен выполнять действия в среде и получать вознаграждение.
3.  **Модульная архитектура:** Система обладает четким разделением ответственности между компонентами, что подтверждается корректной последовательной работой генератора, анализатора, рерайтера и RL-агента.
4.  **Выявленные ограничения (текущие результаты):**
    *   **Качество генерации:** Без проведения тонкой настройки (fine-tuning) GPT-2 на корпусе русской поэзии, генерируемый текст часто является семантически несвязным или шаблонным.
    *   **Эффективность RL:** Функция вознаграждения, основанная на упрощенных метриках, не отражает настоящего поэтического качества. В результате RL-агенту сложно научиться вносить осмысленные улучшения, и его вклад в итоговое качество текста пока незначителен по сравнению с правиловым рерайтером.
    *   **Производительность:** Работа с тяжелыми моделями (BERT, GPT-2) требует значительных вычислительных ресурсов, что замедляет время ответа системы.

### 4. Выводы по работе

1.  **Гибридный подход перспективен:** Комбинация шаблонных методов, нейросетевой генерации, экспертного анализа и RL создает гибкую основу для решения сложной творческой задачи. Каждый компонент решает свою подзадачу, а ядро системы эффективно управляет их взаимодействием.
2.  **Ключ к качеству — в данных и настройке:** Основное ограничение текущей системы — отсутствие специализированных дообученных моделей. **Главным направлением для развития является сбор корпуса русских стихов и проведение тонкой настройки GPT-2 и PoetryCritic на этих данных.** Это фундаментально улучшит связность и поэтичность генерации.
3.  **RL требует сложной функции вознаграждения:** Для того чтобы обучение с подкреплением стало действительно полезным, необходимо разработать многофакторную функцию вознаграждения, которая бы точнее оценивала поэтическую ценность текста, возможно, с привлечением дополнительно обученного критика-эксперта.
4.  **Система является исследовательским стендом:** Разработанная платформа представляет собой полноценный **исследовательский инструмент**. Она позволяет в дальнейшем экспериментировать с архитектурами моделей, методами анализа и стратегиями RL, объективно измеряя их влияние на конечный результат — качество стихотворения.
